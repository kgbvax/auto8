# auto8 v1, automated chasing in FT8 and FT4 - Plan

## 1. Goal

The operator runs WSJT-X or MSHV in FT8 or FT4. auto8 watches the decodes. When a station that the operator
needs calls CQ, auto8 tells the program to answer that station. WSJT-X or MSHV then runs the QSO with its own
auto-sequence. The operator stays at the station and can stop auto8 at any time.

"Needed" is the answer of chase-queue: the enabled goals, the award definitions and the log database
(opsotter `operating/chase-queue/CLAUDE.md`). auto8 does not have a second award logic.

RTTY is not part of v1. A later version can add it, then mostly for contests.

## 2. Scope

In v1:

- WSJT-X over its UDP protocol (`NetworkMessage.hpp` in the WSJT-X source, default port 2237).
- MSHV, to the level that its UDP interface supports (open question 2).
- FT8 and FT4 on the HF bands and 6 m.
- One program instance at a time.

Not in v1:

- RTTY, CW and any contest logic of auto8.
- Control of the radio, the PA, the antennas or the rotators. The program keeps its own CAT control.
- Unattended operation.

## 3. Data flow

```
 WSJT-X / MSHV ──UDP: Status, Decode, QSOLogged──► auto8 ──MQTT: heard CQ stations──► chase-queue
       ▲                                             │  ▲                                   │
       └──UDP: Reply, HaltTx, HighlightCallsign──────┘  └──MQTT: /state ranked rows─────────┘
```

1. The program sends a Decode message for each decoded line. auto8 keeps the CQ and QRZ lines of the
   current cycle: call, grid, SNR, audio offset, band and mode.
2. auto8 publishes these stations as a candidate source for chase-queue (decision D1).
3. chase-queue ranks them with its other rows and publishes `/state`. The rows of auto8 carry `needed` and
   `needs[]`.
4. auto8 picks the best needed row that the program decoded in the last cycle and sends a Reply message for
   that decode line. For WSJT-X, Reply has the same effect as a double-click on the line.
5. auto8 follows the QSO from the Status messages (`dx_call`, `tx_enabled`, `transmitting`) and the
   QSOLogged message. After a logged QSO it sends `handled` to chase-queue, so the station leaves the list
   before the QSO reaches the log database.

## 4. Key decisions (proposed)

- D1. chase-queue ranks the decodes. auto8 publishes a retained state with the heard CQ stations, in the
  shape of bmrec's `cqfinder/state` rows, on its own slot (for example `muehle/hf/auto8`). chase-queue
  reads it as a new source (`source:"auto8"`). This needs a chase-queue change. The other choice, auto8
  calls the award evaluator of `records/logdb/awards` itself, gives a second ranking that can disagree with
  logotter's chase queue column. This plan does not take it.
- D2. Two levels of automation. "Assist" only marks the needed stations in the program with
  HighlightCallsign. "Call" also sends Reply. The operator selects the level. v1 ships "Assist" first.
- D3. auto8 never sets Enable Tx by itself. With "Call", WSJT-X enables TX after a Reply only if the
  operator set "Double-click on call sets Tx enable" in WSJT-X. auto8 shows this setting as a problem when
  it can find it out.
- D4. Presence and arm. auto8 calls stations only while it is armed and the operator is present. Presence is
  logotter's heartbeat (`muehle/hf/logotter/presence`, the same one that chase-queue reads). When the
  heartbeat stops for 90 s, or when the operator disarms, auto8 sends HaltTx and stops.
- D5. Give up. auto8 calls one station for at most a configured number of cycles (default 4). Then it skips
  that station until it calls CQ again after 10 minutes, and goes to the next needed station.
- D6. auto8 does not interrupt a QSO that the operator started by hand. When `dx_call` is set and auto8 did
  not set it, auto8 waits until the QSO is logged or the program is idle for two cycles.

## 5. Risks

- Timing. An FT8 cycle is 15 s and decodes arrive near its end. The round trip from decode to chase-queue
  and back can take 1 to 2 s, because chase-queue publishes at most once per second. A Reply that comes too
  late misses the next slot. auto8 can then answer in the cycle after that, because a CQ station mostly
  repeats its CQ. Measure this in the first phase.
- QSOs from WSJT-X and MSHV do not reach the log database today (open question 3). Until they do, a worked
  station stays needed after a restart of chase-queue or after the `handled` state expires.
- MSHV can support less of the protocol than WSJT-X (open question 2).
- Rules for automatic operation differ by country. The operator is the control operator and must be present.
  D4 makes auto8 stop without the operator.

## 6. Phases

1. Listener. Decode the WSJT-X UDP messages (Heartbeat, Status, Decode, Clear, QSOLogged, Close) and log
   them. Test with recorded datagrams. Measure the decode timing.
2. chase-queue source. Publish the heard CQ stations (D1) and add the source to chase-queue, with its
   contract in opsotter `operating/chase-queue/docs/chase-queue-mqtt-api.md`. That change is made and merged in opsotter by hand, not in this repository.
3. Assist. HighlightCallsign for needed stations, arm and presence (D4), `/state` of auto8 with its problems.
4. Call. Reply, follow the QSO, give up (D5), `handled` after QSOLogged.
5. MSHV. Make sure that phases 1 to 4 work with MSHV, or write down what it does not support.

## 7. Open questions for the operator

1. On which PC do WSJT-X and MSHV run, and does auto8 run on the same PC or on scmino? The UDP protocol works
   best on the same host or with a multicast address.
2. Which MSHV version do you use? Its UDP interface must be tested for Decode, Reply and HaltTx.
3. How do the FT8 and FT4 QSOs reach the log database: an import in logotter, the LoggedADIF message, or
   something else? logotter's use cases (C41 in opsotter `logotter/docs/2026-11-07-operating-surface-use-cases.md`)
   name this need.
4. Is "Call" (D2) wanted in v1, or only "Assist"?
5. Where does the operator arm and disarm auto8 and see its state: in logotter, or in a page of its own?
6. Do you run more than one WSJT-X instance at the same time (for example one per band or radio)?
